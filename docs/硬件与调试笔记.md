# 96×128 HUB75E 点屏实录

替换原 AIR720D + P2064AF2，用 ESP32 / ESP32-S3 直接驱动。

> 面板实际是 **96 宽 × 128 高**（不是 128×96），由两块 **96×64** 模组竖向级联，
> **1/32 扫描、每地址 2 行**。依据开源项目 [hub75e_96_128](https://oshwhub.com/shukkkk/hub75e_96_128)。

---

## 一、面板规格（已确认）

| 项 | 值 |
|---|---|
| 单模组 | 96 × 64 |
| 模组数 | 2 块，上下竖向级联 |
| 整屏 | 96 × 128 |
| 扫描 | 1/32，每地址 2 行 |
| 驱动 IC | 72 × ICN2037BP（16 通道恒流，移位寄存器型） |
| 行扫 | 16 × TC7258GN（双路 MOS）= 32 路地址 |
| 缓冲 | 4 × SM245TS（74HC245）= 32 路 |
| 数据线 | 6 根：R1 G1 B1 R2 G2 B2 |

---

## 二、引脚

### 方案 A：ESP32 经典款（原方案，直接抄官方例程）

| 信号 | GPIO | 信号 | GPIO |
|---|---|---|---|
| R1 | 25 | A | 23 |
| G1 | 26 | B | 19 |
| B1 | 27 | C | 5 |
| R2 | 14 | D | 17 |
| G2 | 12 | E | **32** |
| B2 | 13 | LAT | 4 |
| CLK | 16 | OE | 15 |

> 这套是库里的默认值，只有 `E=32` 是例程里单独指定的。
>
> **推荐板子**：NodeMCU-32S、ESP32-DevKitC —— 引脚完全对得上，代码几乎不用改。
> ⚠️ 必须是 **WROOM** 版（4MB Flash、无 PSRAM）。**WROVER 版不能用**：它的 GPIO16/17 被 PSRAM 占了，而这里 CLK=16。

### 方案 B：ESP32-S3（微雪 S3-ETH 等）

**E 必须换脚** —— S3 的 GPIO32 是 flash 引脚，用不了。把 sketch 里 `USE_S3_BOARD` 改成 1：

| 信号 | GPIO | 信号 | GPIO |
|---|---|---|---|
| R1 | 1 | A | 18 |
| G1 | 2 | B | 38 |
| B1 | 3 | C | 39 |
| R2 | 15 | D | 40 |
| G2 | 16 | E | 41 |
| B2 | 17 | LAT | 47 |
| CLK | 42 | OE | 48 |

这套避开了 S3 的 PSRAM（33~37）、UART0（43/44）、strapping（0/45/46）、USB（19/20）。

## 三、电平转换（必须做）

ESP32 是 3.3V，面板是 5V 逻辑。用 **74HCT245**（HCT，不能用 HC）：

| 245 引脚 | 接法 |
|---|---|
| 1 (DIR) | VCC（A→B） |
| 19 (/OE) | GND（常使能） |
| 20 (VCC) | 5V |
| 10 (GND) | GND |
| A1~A8 | ESP32 GPIO |
| B1~B8 | 面板信号 |

14 根信号需要两片 245。

---

## 四、电源

- 面板 **5V**，满亮约 **2~4A**
- **不能从开发板取电**，USB 那 1A 会被拉垮
- 屏和板**各自供电、可靠共地**
- 上电顺序：接好地线 → 屏上电 → 板上电

## 五、库版本（这个坑必须先说）

本项目自带的库是 **旧版**，API 是：

```cpp
HUB75_I2S_CFG mxconfig(PANEL_RES_X, PANEL_RES_Y, PANEL_CHAIN);
```

新版的类名改成了 `HUB75_I2S_CFLAGS`，**编译不过**。请用附带这份，不要从库管理器装最新版。

## 七、现象对照表

| 现象 | 大概率原因 |
|---|---|
| 能连上但烧录写到一半失败 / 无限重启 `load:0xffff0a00,len:-1` | **GPIO11(CMD) 等 flash 引脚被接地**（本项目实测踩过）；其次是供电和 USB 线 |
| 全黑 | OE 极性 / 245 没供电 / 屏没上电 / E 脚没接 |
| 花屏、雪花 | 少了 245，或引脚接错 |
| 只有 64 行有图像 | `NUM_ROWS`/`PANEL_CHAIN` 没设成 2 |
| 上下两块内容颠倒 | `TOPDOWN` 改成 true，或对调两块的数据顺序 |
| 每隔 8/16 行重复 | 地址线 A/B/C/D 顺序接错 |
| 左右镜像 | 数据位序反了，或 SERPENT 设置 |
| 颜色不对、有条纹 | `driver` 类型选错（试 FM6126A） |
| 闪烁、撕裂 | 提高刷新率，或降 `PIXEL_COLOR_DEPTH_BITS` |
| 跑一会儿重启 | 供电不足（最常见） |

## 九、迁移到新版核心与库（2026-11）

环境从 **arduino-esp32 2.0.17 + 旧版 HUB75 库** 升到 **3.3.12 + 库 3.1.0**，改动如下。

### 1. API 变化

| 旧写法 | 新写法 |
|---|---|
| `VirtualMatrixPanel(disp, rows, cols, w, h, SERPENT, TOPDOWN)` | 第 6 参数换成枚举 `CHAIN_BOTTOM_LEFT_UP_ZZ` |
| `display->setRotate(true)` | `display->setRotation(1)` |
| `setBrightness8()` 在 `begin()` 之前 | 必须在 `begin()` **之后** |
| 依赖库默认引脚 | 全部 14 根显式赋值 |

`CHAIN_BOTTOM_LEFT_UP_ZZ` 的映射公式与旧库 `SERPENT=false / TOPDOWN=false` 完全一致（已逐行核对）。

### 2. 零改库方案：自带逻辑屏映射（推荐）

**不再修改库文件。** 关键点：

- `VirtualMatrixPanel` / `VirtualMatrixPanel_T` 这两个头文件会**强制**
  `#include <Fonts/FreeSansBold12pt7b.h>` 并调用 `setFont()`，
  而 gb2312 精简版 Adafruit GFX 把图形字体整个删掉了 → 编译失败。
- 但基类头文件 `ESP32-HUB75-MatrixPanel-I2S-DMA.h` **是干净的**，不含字体依赖。

所以 sketch 只包含基类，自己继承 `MatrixPanel_I2S_DMA` 实现逻辑屏：

```cpp
class LogicalPanel : public MatrixPanel_I2S_DMA {
  static void mapPoint(int16_t x, int16_t y, int16_t &ox, int16_t &oy);
  void drawPixel(...) override;         // 映射后写 DMA
  void drawFastHLine(...) override;     // 退回 GFX 逐点实现
  void drawFastVLine(...) override;
  void fillRect(...) override;
};
```

映射链路（与旧版驱动库逐项等价）：

```
逻辑 128×96
  → 旋转 90°（vy = VIRT_H-1-x，VIRT_H = 128 是虚拟高度，不是逻辑高度）
  → 竖向级联（vy/64 决定落在 DMA 第 0 / 96 列）
  → 96×64 模组四象限重映射
  → DMA 192×64
```

**已验证**：12288 个逻辑点 → 12288 个物理点，零越界、零重叠，完美一一对应。

> ⚠️ 排查过程中踩过的坑：旋转基准必须用**虚拟高度** `NUM_ROWS*PANEL_RES_Y = 128`，
> 误用逻辑高度 `SCR_H = 96` 会导致 3072 个点映射越界、画面下半部分错乱。

**升级库不再需要任何后续操作。**

### 2b. 历史方案（已废弃）

早期版本曾直接给库打补丁（四象限重映射 + FreeSans 条件编译），
备份在 `_backup/VirtualMatrixPanel-I2S-DMA.h.patched`。
现在改用上面的零改库方案，库文件已还原为原版。
### 3. 字库差异

官方 `Adafruit_GFX 1.13.0` 默认字体是 6×8 点阵，不再是 gb2312 版的 16×16。
代码里的排版函数会按实测字宽自动选字号，所以布局不会错位，但**字号和观感会和之前不同**。
需要中文显示时，换成项目附带的 `Adafruit-GFX-Library_gb2312` 即可，排版逻辑不用改。

### 4. 其他小改动

- `strlen_P()` → `strlen()`（ESP32 上 PROGMEM 是空宏）
- 宏名 `PANEL_CHAIN_TYPE` 改名 `CHAIN_MODE`，避免和库里的枚举类型重名

### 5. 字体库（gb2312 汉化版）

项目使用 `_vendor/Adafruit-GFX-Library_gb2312`（基于 Adafruit GFX 1.4.8，含 `hzk16h.c` 中文点阵），
已安装到 Arduino 的 `libraries/Adafruit_GFX_Library`。
官方 1.13.0 版备份在 `_backup/Adafruit_GFX_Library_official_1.13.0`。

**注意**：新版 HUB75 库无条件 `#include <Fonts/FreeSansBold12pt7b.h>`，而 gb2312 精简版没有 `Fonts/` 目录，
会导致编译失败。已在库中改成条件编译：

```cpp
#if __has_include(<Fonts/FreeSansBold12pt7b.h>)
    #include <Fonts/FreeSansBold12pt7b.h>
    #define VM_HAS_FREESANS_FONT 1
#endif
```

`drawDisplayTest()` 里的 `setFont()` 同样加了 `#ifdef` 保护。这样两种字体库都能编译。

**库补丁清单**（升级库前务必备份这两个文件）：
1. `ESP32-VirtualMatrixPanel-I2S-DMA.h` → 96×64 四象限重映射
2. `ESP32-VirtualMatrixPanel-I2S-DMA.h` → FreeSans 字体条件编译

| 字体库 | Flash 占用 |
|---|---|
| 官方 1.13.0（6×8 点阵） | 1.16 MB (36%) |
| gb2312 汉化版（16×16） | 1.44 MB (45%) |

## 十、局部刷新：标签不跟着闪

问题：数值每秒变化，如果整行清空重画，左边的 `CPU` / `MEM` / `UP` / `DN` 会跟着闪一下。

做法：`drawRowEx()` 把**标签**和**数值**分开缓存。

```cpp
static char    rowLabel[ROW_SLOTS][12];
static char    rowValue[ROW_SLOTS][40];
static int16_t rowValX[ROW_SLOTS];
static int16_t rowLabelX[ROW_SLOTS];
```

- 标签没变 → 一个像素都不碰
- 只有数值变 → 只清 `rowValX` 到屏宽那一块，重画数值
- 标签位置也纳入缓存（空气质量页的列位置会随温湿度宽度变化）

应用范围：PC 页 6 行、空气质量页的 CO2 行（`CO2` 标签也不再闪）。

### 另：PC 页 6 行必须 `PC_TOP = 0`

6 行 × 16px = 96，正好等于屏高。任何下移都会把最后一行（`DN` 下载速率）顶出屏幕。
改用 16px 中文点阵字体后必须去掉这个偏移，否则网速行会消失。

## 十一、字库表：一个必须知道的 C 陷阱

`font8x16.h` 是自带的 8x16 等宽点阵（ASCII 0x20~0x7E，95 个字形），不依赖任何字体库。

**生成时踩过的坑**：在字形行末加注释时，如果注释以反斜杠结尾，例如

```c
{ ... },  // 5C \
{ ... },  // 5D ]
```

C/C++ 在**预处理第二阶段**就会把 `\` + 换行当成续行，于是下一行整行被并入上一行注释。
表现是数组少一个初值，**从该字符起所有字形整体前移一格**。

当时的症状：
- `ug/m3` 显示成 `vh/n3`（u→v、g→h、m→n）
- `KB/s` 显示成 `KB/t`（s→t）
- 大写、数字、`/`、`.` 全部正常（因为都在 `]` 之前）

排查方法（不依赖拍照）：编译后从 `.bin` 里按锚点定位字库表，与头文件逐条比对：

```python
anchor = tbl[0x30-0x20]          # 用 '0' 的字形做锚点
base = d.find(anchor) - (0x30-0x20)*16
ok = sum(1 for i in range(95) if d[base+i*16:base+i*16+16] == tbl[i])
# 修复前 61/95，修复后 95/95
```

**结论：字库文件的注释里绝不要出现行尾反斜杠。**
